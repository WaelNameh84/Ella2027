# Ella2027 Kaggle LTX-2.5 worker (WanGP API)

This branch connects a Kaggle WanGP runtime to the existing Ella2027 PostgreSQL video-job queue. It uses WanGP's supported in-process Python API (`shared.api`), not a temporary Gradio URL. Generated MP4 files are uploaded directly to the existing Cloudinary account using a short-lived signed upload generated by Ella2027.

## Canonical recovery notebook

Use [`notebooks/Ella2027_Kaggle_LTX_Worker.ipynb`](../notebooks/Ella2027_Kaggle_LTX_Worker.ipynb) on branch `feature/ltx25-wangp-api-worker`. It is the single Run All recovery entry point. It installs WanGP dependencies while preserving Kaggle's Torch family, downloads/reuses the model files, writes the local finetune definition, downloads this branch's worker, and starts it in the background with a PID file and log.

## Required secrets

Ella2027 Render API service:
- `KAGGLE_LTX_WORKER_TOKEN` — long random bearer secret.
- Existing Cloudinary configuration: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.

Kaggle Secrets:
- `ELLA_KAGGLE_WORKER_TOKEN` — exactly the same bearer token.

The notebook uses `https://ella2027.onrender.com`. Never commit either token or any Cloudinary secret.

## Worker behavior

The worker claims jobs from `/api/kaggle-worker/claim`, sends heartbeats during generation, submits the scene to WanGP's Python API, validates the resulting MP4 with ffprobe, uploads it to the signed Cloudinary URL, then calls `/complete`. Failures are reported through `/fail`.

## Initial runtime profile

- WanGP model type: `ltx2_25_22B_distilled`.
- Checkpoint: LTX-2.5 22B Distilled NVFP4.
- Text encoder: Gemma 4 12B INT8 ConvRot.
- Initial high-quality output profile: 1024×576 landscape, 576×1024 portrait, or 768×768 square at 24 FPS.
- Maximum scene duration: 10 seconds (conservative local WanGP profile; validate actual runtime memory/time).
- Maximum MP4 upload size: 100 MiB.
- The worker refuses to publish an MP4 without both video and audio streams.

Kaggle T4 does not provide native optimized NVFP4 kernels, so WanGP may use a slower fallback. Actual generation time and output quality depend on the active Kaggle runtime, memory, and upstream compatibility.

## Recovery notes

- `/tmp/ella-ltx25` is ephemeral. A replacement Kaggle runtime must download the model files again.
- The notebook records the detached worker PID at `/kaggle/working/ella_worker.pid` and logs at `/kaggle/working/ella_worker.log`.
- The worker process can continue after the final notebook cell finishes, but it cannot survive Kaggle session shutdown.
- Do not merge this integration into the default branch until end-to-end generation, audio/video validation, Cloudinary upload, and scene completion have been verified.
