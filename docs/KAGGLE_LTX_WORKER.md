# Ella2027 Kaggle LTX-2.5 worker (WanGP API)

This branch connects the Kaggle Wan2GP runtime to the existing Ella2027 PostgreSQL job queue. It uses WanGP's supported in-process Python API (`shared.api`) rather than scraping the temporary Gradio UI. Generated MP4 files are uploaded directly to the existing Cloudinary account using a short-lived signed upload generated by Ella2027.

## Required environment

Ella2027 Render API service:
- `KAGGLE_LTX_WORKER_TOKEN` — long random bearer secret.
- Existing Cloudinary configuration: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.

Kaggle Secrets:
- `ELLA_KAGGLE_WORKER_TOKEN` — exactly the same bearer token.

The notebook already uses the deployed API URL `https://ella2027.onrender.com`. Never put the token in GitHub or notebook source.

## Notebook

Open `workers/ltx25/ltx-2-5-wan2gp-kaggle.ipynb` on this branch. The notebook:
1. Checks the Kaggle GPU and storage.
2. Clones the current Wan2GP source and installs dependencies without replacing Kaggle's Torch family.
3. Downloads/reuses the LTX-2.5 NVFP4 checkpoint and Gemma 4 INT8 text encoder in `/tmp/ella-ltx25`.
4. Downloads `services/kaggle-ltx-worker/wangp_worker.py` from this branch.
5. Starts a persistent polling worker using WanGP's Python API.

The worker claims jobs from `/api/kaggle-worker/claim`, sends heartbeat requests while generating, uploads the MP4 to the signed Cloudinary URL, then calls `/complete`. Failures are reported through `/fail`. The existing API route validates the lease and saves the resulting video into the requested scene.

## Runtime settings and current limits

- WanGP model type: `ltx2_22B_distilled`.
- Initial output profile: 768×448 at 24 fps.
- Maximum scene duration for this first T4 worker: 5 seconds. Longer requests fail explicitly rather than being silently shortened.
- Maximum MP4 upload size: 100 MiB.
- The worker reuses the model/config files in the active Kaggle runtime. `/tmp` is ephemeral across runtime replacement.
- The active WanGP model defaults determine audio-generation options. LTX-2.5 supports audio output, but the presence of model capability alone does not prove that a given preset emitted an audio track. Verify the generated MP4's audio stream during the first end-to-end test.

## Important

Kaggle is not an always-on host. Keep the worker cell running while sending jobs from Ella2027. If the Kaggle session stops, the worker stops polling; the existing five-minute lease allows abandoned jobs to be reclaimed later.

This branch is an integration candidate, not a production claim. Do not merge it into the default branch until a real job has been generated from Ella2027 and its MP4 has been saved back to the correct scene.
